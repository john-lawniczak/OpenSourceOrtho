Additional race hardening prevents an old label import or transferred editor
load from replacing a newer scan. Initial sample loading now disables visit
controls immediately; a quick visit change previously appeared accepted but was
ignored while that first request was pending. Successful server registration also
retains any browser-storage failure warning instead of hiding a session-only
upload behind a success message. Browser tests were also brought into line with
the intentional focused Ask AI composer, sticky guided rail and sample draft
defaults; camera checks retain exact image comparison with stable framing.

## Remaining risks and highest-leverage follow-ups

1. Dense painting remains main-thread work: brush selection scans faces and
   recoloring touches large buffers. Add a reproducible large-mesh latency/memory
   benchmark, then a spatial index or worker only where measured costs justify it.
2. Run the filtered public snapshot in CI, alongside private development. The
   audit exercised a real filtered copy, but routine private-only tests can miss
   future dependencies on excluded paintings and media.
3. Add a portable, source-bound painting bundle containing notes and revision
   metadata. Personal saves now survive reopening in the same browser, but browser
   storage can be cleared or evicted, and the legacy correction JSON contains
   labels without notes.

Week 7 scale and displayed inter-arch separation remain unverified. Saved regions
remain contributor drafts, and motion estimates are distinct from reviewed plan
data. Unknown scanner axes use a heuristic view; universal orientation correctness
cannot be established from one contributed case. Live provider credentials and
all optional native backends were not exercised by this audit. No new confirmed
security defect was found in the reviewed origin, consent, provider-output linting
or release-allowlist paths; this is not a security certification.
